Выводы
Редукция вычисляет одно итоговое значение(например, сумму), 
а сканирование - префиксные суммы для каждого элемента массива.
На больших размерах массива(1e6–1e7) GPU работает быстрее CPU, 
а на маленьких(1024) может быть медленнее из-за накладных расходов запуска ядра и копирования данных.
Оптимизация редукции через shared memory снижает число обращений к глобальной памяти, а warp shuffle ещё ускоряет вычисления, 
выполняя часть суммирования в регистрах внутри warp.
Для сканирования применён Blelloch scan: внутри блока используется shared memory, 
а для больших массивов — иерархическое добавление смещений блоков.
Рекомендации по оптимизации
Редукция: читать по 2 элемента на поток, использовать shared и warp shuffle, подобрать BLOCK(128/256/512).
Scan: использовать Blelloch scan, уменьшать обращения к global памяти и синхронизации, следить за coalesced доступом.
Передача данных: применять pinned memory; при необходимости — cudaMemcpyAsync и streams.
Контрольные вопросы
Разница: редукция → одно число; сканирование → массив префиксных сумм.
Память CUDA: global(данные), shared(ускорение внутри блока), регистры/warp shuffle(ещё быстрее внутри warp).
Оптимизация scan: shared Blelloch + иерархический подход для больших N, меньше global обращений и sync.
Пример применения scan: stream compaction, radix sort, построение кумулятивных сумм/индексов.
