1. Основные типы памяти в CUDA и их скорость
Регистр – очень быстрая, для каждого потока своя, хранит временные переменные.
Shared memory – быстрая, общая для всех потоков блока, идеальна для совместного использования данных.
Глобальная память – большая, но медленная, доступна всем потокам.
Локальная память – на GPU, медленная, создаётся для потоков, когда не хватает регистров.
Константная память – маленькая, быстрая при чтении одним и тем же значением для всех потоков.
2. Когда shared memory ускоряет программу
Когда много потоков блока используют одни и те же данные.
Загружаем данные один раз в shared memory и используем несколько раз, вместо постоянного чтения из глобальной памяти.
Пример: матричное умножение или фильтры для изображений.
3. Как шаблон доступа к глобальной памяти влияет на скорость
Коалесцированный доступ: последовательные потоки читают соседние ячейки → быстро.
Некоалесцированный доступ: потоки читают случайные ячейки → медленно.
4. Почему одинаковый алгоритм может выполняться по-разному
Разная скорость из-за доступа к памяти, кеширования, использования shared memory.
Даже если операции одинаковые, медленно будет, если:
  глобальная память читается хаотично,
  регистры переполнены,
  shared memory перегружена.
5. Как размер блока потоков влияет на скорость
Слишком маленький блок → GPU недозагружен → медленно.
Слишком большой блок → переполнение памяти → медленно.
Оптимальный блок – кратен 32 (warp), например 128, 256, 512 потоков.
6. Что такое warp и зачем его учитывать
Warp = 32 потока, выполняются одновременно.
Если потоки делают разные ветки (if/else), выполнение замедляется.
Поэтому потоков на блок нужно кратно 32 и желательно, чтобы они работали одинаково.
7. На что смотреть при выборе сетки и блоков
Количество потоков на блок → кратно 32.
Количество блоков → чтобы покрыть все данные.
Shared memory и регистры → не превышать лимит GPU.
Коалесцированный доступ к глобальной памяти → быстрее.
Баланс нагрузки между потоками и блоками → все работают одинаково.
