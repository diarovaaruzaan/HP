1)Реализовано гибридное приложение для обработки массива на CPU и GPU. 
Обработка на CPU выполнена с использованием OpenMP, на GPU — с использованием CUDA. 
Также реализован гибридный режим, в котором массив делится на две части и обрабатывается CPU 
и GPU одновременно с применением pinned-памяти, асинхронных копирований и CUDA stream.
2)Результаты замеров
Для массива N = 1 000 000 получены следующие результаты:
CPU OpenMP: 0.625ms
GPU (kernel): 0.111ms
Hybrid: 0.797ms
Корректность подтверждена: GPU = OK, Hybrid = OK.
3)Анализ производительности
GPU обеспечивает высокую скорость вычислений, однако гибридный режим оказался медленнее CPU 
из-за накладных расходов передачи данных и синхронизации. Для простой операции выигрыш от GPU 
не перекрывает затраты на копирование. Гибридный подход эффективен при более сложных 
вычислениях и перекрытии передачи данных с вычислениями.
4) Выводы
Когда гибрид эффективен:
при больших объёмах данных,
при вычислительно сложных операциях,
при хорошем балансе нагрузки CPU/GPU.
Факторы производительности:
скорость передачи CPU↔GPU,
баланс нагрузки,
накладные расходы kernel и синхронизации,
тип памяти и параметры запуска.
Оптимизация передачи данных:
pinned memory,
cudaMemcpyAsync и streams,
уменьшение числа копирований,
обработка данных чанками.
Контрольные вопросы
1) Преимущества гибридных вычислений
Позволяют совместно использовать CPU и GPU, повышая производительность для сложных и масштабных задач.
2) Минимизация накладных расходов
Pinned memory, асинхронные копирования, streams и перекрытие передачи данных с вычислениями.
3) CPU vs GPU
CPU — управление, ветвления, небольшие данные.
GPU — массовые параллельные операции над большими массивами.
4) Улучшение производительности
Баланс CPU/GPU, усложнение вычислений на GPU, использование streams, оптимизация памяти и параметров запуска.
